01 · What this is01 · ما هذا

What you're setting up.ما الذي ستُعدّه.

Charlie Hills gave Claude's two top models the same 7 build prompts in Claude Code on Nov 10, 2026. One shot each, no fixes. Every prompt asked for a single self-contained HTML file built with Three.js: a black hole, robot arms solving a Rubik's cube, a 3D shooter, a smart speaker, a product configurator, a sales globe and a retro shooter. Fable's versions looked richer on almost every one. On the one build that needed real logic, the Rubik's cube, only Opus wrote a real solver.أعطى Charlie Hills أقوى نموذجين لدى Claude الأوامر السبعة نفسها في Claude Code بتاريخ 10 نوفمبر 2026، محاولة واحدة لكلٍّ منها بلا أي تصحيح. طلب كل أمر ملف HTML واحدًا مستقلًا مبنيًا بـ Three.js: ثقب أسود، وذراعان آليتان تحلّان مكعب روبيك، ولعبة تصويب ثلاثية الأبعاد، ومكبّر صوت ذكي، وأداة لتخصيص منتج، وكرة أرضية للمبيعات، ولعبة تصويب بطابع قديم. بدت نسخ Fable أغنى في كل المشاريع تقريبًا. وفي المشروع الوحيد الذي احتاج منطقًا حقيقيًا، مكعب روبيك، كان Opus الوحيد الذي كتب حلًّا فعليًا.

The gap comes from two places. Per token, Fable 5.2 costs twice what Opus 5.5 does on the API ($8 in and $40 out per million tokens, against $4 and $20). And on the 4 builds Charlie timed, Fable also ran longer. His fix is to run both: Opus builds, Fable checks the hard parts. That setup ran all 7 for $25.81.يأتي الفرق من مصدرين. سعر Fable 5.2 لكل رمز (token) ضعف سعر Opus 5.5 عبر API: ثمانية دولارات للإدخال وأربعون للإخراج لكل مليون رمز، مقابل أربعة دولارات للإدخال وعشرين للإخراج لدى Opus. وفي المشاريع الأربعة التي قاس Charlie وقتها، استغرق Fable وقتًا أطول أيضًا. والحل الذي يقترحه هو تشغيل الاثنين معًا: Opus يبني وFable يراجع الأجزاء الصعبة. نفّذ هذا الإعداد المشاريع السبعة بـ 25.81 دولارًا.

You needما تحتاجه

  • Claude Code v2.1.321 or later (Fable 5.2 needs it)
  • Fable access. Max, Ultra and Team or Enterprise premium seats use plan limits, capped at 50% of the weekly limit. Pro and standard seats bill Fable to usage credits, except Pro's launch window, which ends Nov 16, 2026 at 11:59 pm PT
  • Claude Code signed in through Anthropic directly (a Claude plan or an API key). The advisor doesn't run on Amazon Bedrock, Google Cloud or Microsoft Foundry
  • One build prompt to test with: one of Charlie's 7, or a real job from your business
  • Claude Code بالإصدار v2.1.321 أو أحدث (يحتاجه Fable 5.2)
  • إمكانية استخدام Fable. خطط Max وUltra والمقاعد المميزة في Team وEnterprise تستخدم حدود الخطة بسقف 50% من الحد الأسبوعي. أما Pro والمقاعد العادية فتحتسب Fable من رصيد الاستخدام الإضافي، باستثناء فترة إطلاق Pro التي تنتهي في 16 نوفمبر 2026 الساعة 11:59 مساءً بتوقيت المحيط الهادئ
  • Claude Code مسجّل الدخول عبر Anthropic مباشرة (خطة Claude أو مفتاح API). لا يعمل المستشار على Amazon Bedrock أو Google Cloud أو Microsoft Foundry
  • أمر بناء واحد للاختبار: أحد أوامر Charlie السبعة، أو مهمة حقيقية من عملك
Heads up:تنبيه: These numbers are one run per build, from one person, priced at API rates. Your bill will be different, so treat it as a direction, not a quote. On a plan, Fable eats your weekly limit faster than other models, and on Pro after Nov 16 it bills usage credits. In non-interactive mode (claude -p) Claude Code bills those credits without asking. Check /usage after every run.هذه الأرقام من تشغيل واحد لكل مشروع، ومن شخص واحد، ومحسوبة بأسعار API. فاتورتك ستختلف، فاعتبرها مؤشرًا لا عرض سعر. على الخطط، يستهلك Fable حدّك الأسبوعي أسرع من النماذج الأخرى، وعلى Pro بعد 16 نوفمبر يُحتسب من رصيد الاستخدام الإضافي. وفي الوضع غير التفاعلي (claude -p) يحتسب Claude Code هذا الرصيد دون أن يسألك. راجع /usage بعد كل تشغيل.

03

Put Opus on the buildاجعل Opus يبني

Open Claude Code in an empty folder and set Opus 5.5 as the main model. Opus does the building.افتح Claude Code في مجلد فارغ واجعل Opus 5.5 النموذج الرئيسي. Opus هو من يبني.

/model opus
04

Turn on Fable as the advisorفعّل Fable مستشارًا

Claude now calls Fable at the hard moments: before it picks an approach, when an error keeps coming back, and before it says it's done. You'll see an Advising line when it does. If Claude Code points you to /model fable instead, your plan needs a one-time OK to bill Fable to usage credits: accept it there, switch back with /model opus, then run /advisor fable again.سيستدعي Claude الآن Fable في اللحظات الصعبة: قبل أن يختار طريقة العمل، وعندما يتكرر خطأ ما، وقبل أن يعلن انتهاءه. سترى سطر Advising عندما يحدث ذلك. إذا وجّهك Claude Code إلى /model fable بدلًا من ذلك، فخطتك تحتاج موافقة لمرة واحدة على احتساب Fable من رصيد الاستخدام الإضافي: وافق هناك، ثم عُد بـ /model opus، ثم شغّل /advisor fable مرة أخرى.

/advisor fable

05

Paste one prompt, take the first tryالصق أمرًا واحدًا وخذ المحاولة الأولى

Paste one of prompts 1 to 7 once and let it finish. No fixes, no follow-ups, or the comparison means nothing. When it's done, open the file it built, then run /usage and write down what the session used.الصق أحد الأوامر من 1 إلى 7 مرة واحدة واتركه حتى ينتهي. لا تصحيح ولا أسئلة متابعة، وإلا تفقد المقارنة معناها. عندما ينتهي، افتح الملف الذي بناه، ثم شغّل /usage وسجّل ما استهلكته الجلسة.

/usage
06

Run it on Fable alone and compareنفّذه على Fable وحده وقارن

Turn the advisor off, start a fresh session in a new folder, switch to Fable and paste the exact same prompt. First try again. Put both results side by side and compare the build and the bill. Then decide which jobs earn Fable and which ones Opus handles fine.أوقف المستشار، وابدأ جلسة جديدة في مجلد جديد، وانتقل إلى Fable، والصق الأمر نفسه تمامًا. المحاولة الأولى مجددًا. ضع النتيجتين جنبًا إلى جنب وقارن البناء والفاتورة. ثم قرّر أي المهام تستحق Fable وأيها يكفيها Opus.

/advisor off
/model fable

03 · Copy and paste03 · انسخ والصق

Your prompts.أوامرك الجاهزة.

انسخ الأوامر والنصوص كما هي باللغة الإنجليزية، فهي تعمل بدقة أكبر.

PROMPT1. Black hole1. الثقب الأسود

Build a single self-contained HTML file with Three.js: a black hole with a glowing, swirling accretion disk and light bending around it.
I can orbit with the mouse and zoom with the scroll wheel.
Put everything in one index.html I can open in the browser, no build step.

PROMPT2. Robot arms2. الذراعان الآليتان

Build a single self-contained HTML file with Three.js: two robot arms that solve a scrambled Rubik's cube, animated move by move.
Add a Scramble button and a Solve button. The cube must end fully solved.
Put everything in one index.html I can open in the browser, no build step.

PROMPT3. 3D shooter3. لعبة التصويب ثلاثية الأبعاد

Build a single self-contained HTML file with Three.js: a playable third-person cover shooter.
WASD to move, mouse to aim, click to shoot, crates to hide behind, enemies that shoot back, health and score on screen.
Put everything in one index.html I can open in the browser, no build step.

PROMPT4. Smart speaker4. السمّاعة الذكية

Build a single self-contained HTML file with Three.js: a smart speaker that assembles itself part by part (base, drivers, fabric mesh, top ring with lights), then turns slowly.

PROMPT5. Product configurator5. أداة تخصيص المنتج

Build a single self-contained HTML file with Three.js: a 3D product configurator for a sneaker.
Colour swatches and 3 materials change the model live, the price updates with each option, and I can rotate it with the mouse.
Put everything in one index.html I can open in the browser, no build step.

PROMPT6. Sales globe6. كرة المبيعات الأرضية

Build a single self-contained HTML file with Three.js: a 3D globe that shows sales by city as glowing bars, with sample data for 20 cities.
Hovering a bar shows the city and the revenue. The globe turns slowly on its own.
Put everything in one index.html I can open in the browser, no build step.

PROMPT8. Judge the two builds8. قيّم النسختين

I ran the same prompt on two models. Their builds are in [folder A] and [folder B].
Open both files and compare them on: does it work, does it do everything the prompt asked, and how good does it look.
List what each one got wrong. Don't tell me which model made which.

PROMPT9. Turn a real job into a test9. حوّل مهمة حقيقية إلى اختبار

Here's a task I do in my business every week: [describe it].
Turn it into one prompt I can paste into Claude Code and run once, with no fixes, on two different models.
Spell out exactly what done looks like, so I can judge both results the same way.
