01 · What this is

What you're setting up.

A skill is a saved employee, not a saved prompt. It's a folder on your computer with one file in it. That file tells Claude Code how to do a specific job: the exact steps, the format, the tools it should use. You type /your-skill-name, Claude reads the file, and does the job the same way every time. Like handing an SOP to a new employee, except this one runs 24/7, doesn't forget, and costs pennies.

You do not need to code. You write instructions in plain English inside a text file. A prompt is typed fresh each time, lives in your head, drifts, and dies when you close the chat. A skill is written once, lives in a file, carries your context, and is there every session, every project. Stop asking "what should I type next?" Start asking "what process do I keep repeating that should live in a file?"

You need

  • A Mac or Windows machine
  • An Anthropic account (Claude Code asks you to log in on first run)
  • One process you keep repeating that should live in a file
Heads up: If your skill never fires, it's almost always the description or the folder. "Helps with X" is invisible to Claude. And global skills go in ~/.claude/skills/, not ~/claude/skills/. The dot matters.

02 · The steps

Set it up, step by step.

01

Install Claude Code

Two minutes. One command. Mac: open Terminal (⌘ + Space, type "Terminal", enter) and paste the first line. Windows: open PowerShell (Start, type "PowerShell", enter) and paste the second. Then type claude in the same window and hit enter. First run asks you to log in with your Anthropic account. Do it once. That's the only Terminal moment in this guide, from here everything happens inside Claude Code.

# Mac (Terminal)
curl -fsSL https://claude.ai/install.sh | bash

# Windows (PowerShell)
irm https://claude.ai/install.ps1 | iex

# Then launch it
claude
02

Paste the install prompt into Claude Code

You don't have to create folders or files yourself. Open Claude Code, paste the "Install 3 skills" prompt below, hit enter. Claude does the whole install: 3 skills, wired up, ready to run. Then restart Claude Code (quit + relaunch). Type / and you'll see /weekly-review, /client-recap and /hook-remix in the menu.

03

Write the description, it's the whole game

Claude reads the description and decides whether your skill applies to what the user just asked. The name becomes your slash command (/daily-standup). Vague description = Claude ignores your skill and keeps improvising. "Helps with standup updates." won't fire: no trigger words, no input, no output. "Generate a daily standup update by scanning today's calendar events and yesterday's git commits. Use when the user asks for a standup, asks what they did yesterday, or needs a status update for their team." fires reliably because it names the output, the inputs and the trigger situations. The formula: [What it does] by [how it does it]. Use when [trigger situation 1], [trigger situation 2], or [trigger situation 3].

---
name: daily-standup
description: [THIS IS THE WHOLE GAME]

04

Write the body, the SOP Claude follows

Everything under the frontmatter is the actual playbook. Treat it like onboarding a new hire on day one: explicit, numbered, zero assumptions. Claude will do exactly what you write. Not more. Not less. Here's the full SKILL.md for /daily-standup, end to end.

---
name: daily-standup
description: Generate a daily standup update by scanning today's calendar events and yesterday's git commits. Use when the user asks for a standup, asks what they did yesterday, or needs a status update for their team.
---

# Daily Standup

Generate a 3-bullet standup update in the "Yesterday / Today / Blockers" format.

## Steps

1. Run `git log --since="yesterday" --until="today" --author="$(git config user.email)" --oneline` in the user's active repos. Pull the commit messages.

2. Read today's calendar events (use the calendar MCP if connected, otherwise ask the user to paste them).

3. Summarize yesterday's commits into 1-2 bullets, what shipped, what's in progress. Skip noise commits (typos, formatting).

4. Pull today's calendar to list what the user is heads-down on.

5. Ask the user one question: any blockers? If yes, add as third bullet. If no, write "None."

## Output format

**Yesterday:** [1-2 bullets of what shipped]
**Today:** [1-2 bullets from the calendar, meetings + focus blocks]
**Blockers:** [user's answer, or "None"]

Copy the final output to clipboard.
05

Run the 30-second test

A skill that never triggers is just a markdown file. Open Claude Code in any project and type /daily-standup. If the slash menu autocompletes your skill name, the file is being read. Hit enter and watch: does it follow your steps, ask for the right inputs, match your format? If yes, ship it. If no, open the SKILL.md, fix the gap, save, rerun.

/daily-standup
06

Fix it when it won't fire

Description too vague: rewrite it with the formula. No trigger phrases: add 2-3 specific situations ("Use when the user asks for X, mentions Y, or types Z"). Wrong folder: global goes in ~/.claude/skills/, not ~/claude/skills/. Overlaps another skill: Claude picks one and the more specific one wins, so tighten yours. Most skills take 3-4 rewrites of the description before they fire reliably. That's normal.
